# Wheelchair Friendly Campus Navigation using A*, an Accessibility Aware Heuristic, and Dijkstra's Algorithm

SIT215 Computational Intelligence, Assignment 1 (Problem Solving).

## Purpose and problem

Route planners such as Google Maps mostly minimise distance and ignore accessibility features such as slopes, missing
kerb ramps, obstacles, rough surfaces and lifts. This project models a small **fictional campus** as a graph and
plans routes for a wheelchair user with **A\*** and **Dijkstra's algorithm**, both written from scratch on an
**adjacency matrix**. Each path segment has a physical length and accessibility attributes, and the route cost is

    cost = length x (1 + alpha x (slope/5 + rough)) + alpha x feature penalty

where `alpha` scales every accessibility penalty. `alpha = 0` gives plain distance (Task 2, basic navigation) and
`alpha = 1` gives the accessibility-aware cost (Task 3 onward). The cost unit is an "effort-equivalent metre".

The code compares three searches on identical graphs and costs:

* **Dijkstra**: expands the cheapest-so-far node first (`f = g`); uses no heuristic.
* **A\* with h1**: `f = g + h1`, where h1 is the straight-line (Euclidean) distance to the goal. Because every segment
  costs at least its length, h1 never overestimates and is consistent.
* **A\* with h2 (gateway heuristic)**: on the same level as the goal h2 equals h1. On the other level, h2 is the minimum
  over the currently available level connectors of *(straight line to the connector + the connector's real cost +
  straight line from the connector to the goal)*, because every cross-level route must use a connector. Only connector
  costs enter h2; it does not add penalties for individual rough, obstacle or missing-ramp segments elsewhere.
  **h2 is rebuilt from the current cost matrix for every query** (`astar_gateway`), because a stale h2 can overestimate
  after a connector cost decreases. Closed connectors (`INF`) are ignored.

"Nodes expanded" is the number of nodes closed until the goal is popped (the goal counts). It is the primary,
deterministic efficiency metric; runtime is secondary.

## Important notes on the data

* The campus is a **deterministic simulated environment** (32 nodes, 51 segments, two levels joined by three connectors:
  a hillside ramp, a lift and a service road). **All coordinates, slopes, surfaces, kerb-ramp/obstacle/lift features and
  penalty values are simulated assumptions. They are not real-world measurements.** The environment is frozen and
  checked by a fingerprint.
* **E3 and E4 use synthetic benchmark graphs** (grids generated by fixed rules and seeds). They are controlled
  scalability and constraint-density studies, **not** campus maps, and their results should not be read as results for
  a real campus.
* E4 uses nominal 25%, 50% and 75% constraint levels. The implementation constrains **79, 158 and 238 of the 317
  segments**, which are 24.9%, 49.8% and 75.1% (rounded counts, not exact percentages).
* **Runtime values are machine-dependent** (tested on Python 3.9.6, macOS, Apple silicon). The runtime statistics, and the
  number of timing repeats chosen in E3 and E4, change from run to run. Routes, costs, expansion counts, heuristic values
  and the other search results are deterministic and were reproduced identically on regeneration.
* In `results/e1_comparisons.csv`, the `iqr_*` columns hold the runtime classification: the 5% descriptive runtime-band
  classification followed by the interquartile-range summary. The 5% band is a practical descriptive threshold, not a
  statistical test.

## How to run

Run all commands from this folder.

| Command | What it does | Approx. time |
|---|---|---|
| `python wheelchair_nav.py` | same as `validate` (the default) | about 1 s |
| `python wheelchair_nav.py validate` | runs all validation suites, prints them, and saves `results/v0_validation_log.txt`; writes no experiment CSVs or figures | about 1 s |
| `python wheelchair_nav.py e1` | E1: ten named scenarios, Dijkstra vs A\* h1 vs A\* h2, alpha = 1 and 0 (also redraws the campus maps) | about 3 s |
| `python wheelchair_nav.py e2` | E2: alpha sensitivity, alpha = 0, 0.5, 1, 2, plus a fine alpha scan for route change points | about 4 s |
| `python wheelchair_nav.py e3` | E3: synthetic scalability benchmark, 20 to 800 nodes | about 40 s |
| `python wheelchair_nav.py e4` | E4: synthetic constraint-density sweep on a fixed 100-node graph | about 20 s |
| `python wheelchair_nav.py all` | validation, then E1 to E4 | about 1.5 min |

**Warning:** `e1`, `e2`, `e3`, `e4` and `all` **overwrite** their CSVs, text reports and figures in `results/` and
`figures/`. Only the runtime columns (and the redrawn figures' runtime values) will differ from the submitted outputs.
Running the program with no argument is safe: it only validates.

## What `validate` checks

Environment data (counts, connectivity, cost ordering, connectors, frozen fingerprint), the adjacency matrices (INF
handling, symmetry, alpha = 0 gives distance, alpha = 1 formula, closures), the A\* baseline (hand-calculated cases,
start = goal, unreachable goal, tie-breaking), Dijkstra (including A\* with h = 0 being identical to Dijkstra, and
agreement with an independent Floyd-Warshall reference on every ordered pair), and the h2 suite (admissibility,
consistency, dominance over h1, closures, cost increases, and the stale-versus-rebuilt cost-decrease test).

## Generated outputs

* `results/v0_validation_log.txt`: the validation output saved by `validate`.
* `results/e1_*`: `e1_runs.csv` (every scenario x alpha x algorithm), `e1_comparisons.csv`, `e1_report.txt`.
* `results/e2_*`: `e2_runs.csv`, route-switch tables (`e2_route_switches_sampled.csv`, `e2_change_points_exact.csv`,
  `e2_route_intervals_exact.csv`), `e2_distance_tradeoff.csv`, tightness tables (`e2_tightness_*.csv`), `e2_report.txt`.
* `results/e3_*`: `e3_runs.csv`, `e3_summary.csv`, `e3_graphs.csv`, `e3_report.txt` (generation rules, seeds, pairs, results).
* `results/e4_*`: `e4_runs.csv`, `e4_summary.csv`, `e4_tightness.csv`, `e4_levels.csv`, `e4_contour_diagnostic.csv`,
  `e4_report.txt`.
* `figures/`: `fig1_campus_map_*.png` (campus maps), and `fig_e1_*`, `fig_e2_*`, `fig_e3_*`, `fig_e4_*` (experiment figures).

repeated runs with garbage collection disabled and reports medians.
